# H₂ TT Receiving / Dynamic Lab v0.2.0

수소 튜브트레일러 수취용 오프라인 시뮬레이터. **1 TT + 1~32 Bank**, 직접 균압 / 등가 압축 회수 템플릿을 지원합니다. v0.1의 물성·Cv·재고 계산을 유지하면서 Bank 구성, 조건 로직, 운전 SP, 명령 우선순위, 지연 차단을 확장했습니다.

**현장 PLC, 밸브 또는 압축기와 통신하지 않습니다.** 모든 Setpoint와 보호동작은 모의실험 입력입니다. 실제 설비의 C&E/보호설정·PSV 해석을 대신하지 않습니다.

## 1. 실행

Python 3.10 이상, Tkinter. 기본 실행에 pip 패키지는 필요하지 않습니다.

- Windows: 압축 해제 → `run_windows.bat` 실행
- 명령행: `python main.py`
- 단일 실행본: `python H2_TT_Dynamic_v0_2.py`
- Tk 확인: `python -m tkinter`
- 선택 물성만: `pip install CoolProp` 후 EOS를 CoolProp으로 선택

```bash
# 자동 균압 후 압축 회수
python main.py --headless --auto --hours 18 --out results/auto

# 5-Bank 예제
python main.py --config examples/five_bank_receiving.json --auto

# 압력조건 STOP 시험
python main.py --config examples/pressure_rule_stop.json --auto

# 자동모드를 유지하는 예약 밸브 개폐
python main.py --config examples/auto_preserving_valve_pulse.json --auto

# 자동 시험
python -m unittest discover -s tests -v
```

GUI 입력창의 `JSON 열기`로 예제를 읽은 후 `균압 → 압축 회수 시작`을 눌러도 됩니다.

## 2. 이번 개정에서 추가한 기능

| 기능 | 구현 |
|---|---|
| Bank 구성 | 1~32개 추가/수정/삭제; 임의 이름; 각 Bank의 용적·온도·초기압력·목표·HH |
| 자동 순서 | Bank 이름 목록으로 균압/회수 순서 지정; 3개로 고정하지 않음 |
| 계통 템플릿 | 균압+압축 회수 / 균압만 / 전량 압축 |
| 조건 로직 | 압력·유량·차압·개도·상태의 ALL(AND)/ANY(OR), 유지시간, 복귀조건 |
| 출력 유지 | WHILE / LATCH / ONCE |
| 실시간 SP | 초기화 없이 목표·종료·HH·흡입 SP·타이머 변경, 변경 이력 기록 |
| 우선순위 | STOP/보호/인터록/수동/조건/예약/시퀀스 구분; 출력 소유자 표시 |
| 예약 동작 | automatic(AUTO 유지) / operator(MANUAL 전환) 구분 |
| 종료응답 | IDEAL / DELAYED, 개방·폐쇄 전행정 및 압축기 등가 감속 |
| 추가 유입 | 차단 요청→완료 사이 추가 유입량·압력, 최대압력 기록 |
| 기록 | 전체 표본은 임시 파일 기록; 화면은 최근 30,000개, CSV는 전체 기록 |
| 호환성 | v0.1 JSON 입력 가능. IDEAL·정지 ramp 0으로 이관 |

계통은 여전히 **1 TT–2개 선택경로–단일 선택 Bank 충전** 구조입니다. 자유 배관망, 복수 TT 동시 인입, 수요처 동시 인출은 이번 개정에 포함하지 않았습니다.

## 3. 화면 조작

### 3.1 설비 구성: 새 실험을 만들 때

상단 `설비 구성`을 누릅니다. 이 화면은 모사를 일시정지합니다.

1. `TT / Bank 구성`: TT 내용적·초기압력·온도 입력, Bank 추가/수정/삭제.
2. `밸브 Cv / 응답`: 밸브 선택 후 정격 Cv, 개방 전행정, 폐쇄 전행정, 특성, R 입력.
3. `압축기 / 물성`: 등가 압축기 정격, 기동/정지 ramp, 물성모델 입력.
4. `시퀀스 / 차단`: 충전 순서, 자동 형식, 차단모드, 시간간격 지정.
5. `새 실험으로 적용`: 재고·시간·이력 초기화. 현재 결과는 먼저 저장합니다.

Bank 이름은 영문으로 시작하고 영문/숫자/밑줄/하이픈, 24자 이내입니다. Bank 이름을 바꾸려면 삭제 후 추가합니다. 사용 중인 규칙·예약에서 삭제할 Bank를 참조하면 삭제를 거부합니다. 원치 않는 규칙을 조용히 삭제하지 않습니다.

Bank별 연결밸브 `BANK-이름`은 자동 생성됩니다. 전체 내용적을 입력합니다. 예: 1.3 m³ × 9본 = 11.7 m³.

`compressor_enabled=False`일 때 `EQUALIZE_ONLY`를 사용합니다. 공통 밸브 Tag는 템플릿의 장치 식별자입니다.

### 3.2 운전 SP: 재고·시간을 유지하고 바꿀 때

상단 `운전 SP` → 값을 변경 → `상태 유지하고 적용`.

변경 가능:
- TT 종료압력
- Bank별 목표압력·HH, 공통 HH
- 균압 종료차압·연속 확인시간
- 이상 Regulator 흡입 SP 및 최소흡입압력
- 밸브 동작 Timeout / 압축기 무유량 지연
- 수동 목표정책

질량·온도·시간·기존 그래프를 재초기화하지 않습니다. 입력오류가 있으면 전체 변경을 취소하고 이전 상태를 유지합니다. `events.csv`의 `SP_CHANGE`에 이전/새 값이 기록됩니다.

**현재압력보다 목표를 낮추면 다음 제어 평가에서 종료 절차가 시작**됩니다. HH를 현재압력 아래로 변경하면 즉시 보호정지가 요청됩니다. DELAYED에서는 실제 밸브 폐쇄가 끝날 때까지 적분해야 합니다.

Bank별 HH를 개별 지정한 경우 공통 HH보다 개별값을 사용합니다. 운전 SP 창의 Bank HH 칸은 적용 시 개별값으로 저장됩니다.

설비 크기·초기상태·Cv·개폐시간·물성·시퀀스 순서·차단모드는 `설비 구성`에서 새 실험으로 변경합니다.

### 3.3 밸브와 압축기

- 밸브 심벌 클릭: CMD(명령)/ACTUAL(실개도), Cv, 개방/폐쇄시간, 출력 소유자 확인.
- `수동 적용`: MANUAL로 전환해 조작. 보호/인터록에 막히면 실제 출력은 명령과 다를 수 있습니다.
- `수동/예약 해제`: 해당 수동·예약 출력을 제거하여 하위 자동명령에 권한을 돌려줍니다.
- `정상 STOP`: 전체 정상 종료 절차. 시간 적분을 계속하여 폐쇄 완료를 확인합니다.
- `SIM ESD`: 모의 보호정지 및 래치. DELAYED는 액추에이터 이동시간 반영.
- `TRIP Reset`: 원인 해소·밸브 닫힘·압축기 정지 후, 재고와 시간을 유지하여 READY 복귀. 자동 재기동하지 않습니다.

`일시정지`는 계산시간을 멈추는 것이며 밸브 CLOSE가 아닙니다. RUN 배속은 물리적 개폐시간과 별개입니다.

## 4. 조건별 밸브 OPEN/CLOSE 설정

아래 `조건 로직` 탭 → `추가`를 누릅니다.

### 예: Bank C 압력이 150 barg 이상인 상태가 2초 지속되면 정지

| 항목 | 입력 |
|---|---|
| 규칙 이름 | `Bank_C_Pressure_Stop` |
| 운전모드 / 단계 | AUTO / EQ 또는 ANY |
| 조건 1 | `bank.C.pressure >= 150` |
| 조건 2 | `flow_kg_h > 0` |
| 조건 결합 | ALL |
| 발동 유지시간 | 2 s |
| 동작 | `stop` |
| 유지방식 | ONCE |

### 예: 조건 동안 BYPASS 밸브를 닫기

- 동작 종류: `valve`
- 대상: `BYPASS`
- 값: `0`
- NORMAL 규칙은 수동 출력보다 낮습니다. 수동 OPEN을 강제 차단하는 모의 보호·인터록 규칙은 `PROTECTION` 또는 `INTERLOCK`을 선택합니다.
- 보호/인터록 우선순위에서는 CLOSE/STOP/TRIP만 허용합니다.

### 감시변수

`tt.pressure`, `bank.A.pressure`, `selected.pressure`, `selected.dp`, `flow_kg_h`, `valve.BYPASS.opening`, `mode`, `phase`, `route` 등.

- 압력: barg / 차압: bar / 유량: kg/h / 개도: % / 시간: s.
- `selected.dp` = TT 압력 − 현재 선택 Bank 압력.
- 상태문자열은 `==` 또는 `!=`로 비교합니다.
- 코드/수식 문자열은 실행하지 않습니다. 정의된 변수와 비교연산만 사용합니다.

### 유지·복귀

| 방식 | 의미 |
|---|---|
| WHILE | 발동조건 유지 중 출력 적용. 복귀조건을 넣으면 그 조건을 만족할 때 해제 |
| LATCH | 발동 후 조건이 해제되어도 출력 유지. 복귀조건 또는 수동 Reset으로 해제 |
| ONCE | 한 번 발동하고 출력 유지. 해제 후에도 수동 Reset 전에는 다시 발동하지 않음 |

예: 120 barg 이상 CLOSE, 115 barg 이하 복귀를 입력하면 히스테리시스입니다. **이번 모델은 Bank 인출·냉각이 없으므로 격리한 Bank의 압력이 저절로 115 barg까지 내려가지 않습니다.** 복귀 시험은 조건·입력 시나리오에 맞춰 수행해야 합니다.

활성화된 보호/인터록 규칙은 원인 해소 및 Reset 전에 수정·삭제할 수 없습니다. 발동조건이 계속 유지되는 규칙의 수동 Reset도 거부합니다.

밸브·압축기 출력은 활성 상태 동안 계속 적용합니다. `bank`, `route`, `next`, `stop`, `trip` 등 절차 동작은 발동 순간 한 번 요청합니다. 경로/Bank/NEXT 변경 규칙은 AUTO에서 적용하며, MANUAL에서는 운전자 선택을 우선하여 거부합니다.

## 5. 조작 권한

출력 우선순위(숫자가 클수록 우선):

1. 전체 STOP/TRIP 절차 및 종료 래치: 100
2. 하드 계통 인터록(한 Bank, 경로 상호배타, 기동 유로): 90
3. PROTECTION 규칙: 80
4. INTERLOCK 규칙: 70
5. 운전자 수동 출력: 60
6. NORMAL 조건규칙: 50
7. AUTO 유지 예약 출력: 40
8. 기본 시퀀스: 20

동일 우선순위가 충돌하면 더 작은 개도/STOP을 우선합니다. 같은 우선순위로 서로 다른 Bank를 동시에 열도록 요청하면 Bank 개방을 차단합니다.

**`stop` / `trip` 절차 요청은 명령 출처와 무관하게 전체 정지 권한으로 처리**합니다. 정상 규칙의 OPEN이나 예약 OPEN은 종료 래치를 해제하지 않습니다. 명시적인 재시작·수동전환이 필요합니다.

자동 `release`는 예약 출력만 해제합니다. 운전자 `release`는 수동/예약 출력을 해제합니다. 규칙 해제는 해당 규칙의 복귀/Reset으로 수행합니다.

## 6. 시간 이벤트

`개폐 이벤트`에서 시각, 밸브, 개도, 권한을 선택합니다.

- `automatic`: AUTO를 유지하며 예약 출력 적용. 후속 이벤트·해제 또는 다음 자동 단계 진입까지 유지.
- `operator`: MANUAL로 전환하며 수동 출력 적용.
- v0.1 JSON에서 권한 필드가 없으면 이전 의미인 operator로 읽습니다.

JSON 이벤트에는 `valve`, `bank`, `route`, `compressor`, `release`, `auto`, `manual`, `stop`, `estop`을 사용할 수 있습니다. GUI 예약창은 밸브 개도 예약을 지원합니다.

## 7. 종료 응답

### IDEAL

차단명령 시 실제 개도와 압축기 속도를 즉시 0으로 변경합니다. TT 종료재고/Bank 목표재고에서 이송질량을 제한합니다. 기존 재고 계산을 비교할 때 사용합니다.

### DELAYED (v0.2 기본)

- 목표/종료 조건 → 명령 생성 → 액추에이터 이동 → 실제 유량 변화 → 폐쇄 확인.
- 정상 압축회수 정지는 등가 구동 감속 동안 유로를 유지하고, 속도 0 이후 경로를 닫습니다.
- TRIP은 모든 밸브에 즉시 CLOSE 명령을 내리되 유한 폐쇄시간을 적용합니다. 압축기는 지정 감속시간을 적용합니다.
- 폐쇄 중 잔류 유량을 계속 계산하며 Bank 목표압력이나 TT 종료압력에서 질량을 강제로 잘라내지 않습니다.
- 압력이 EOS/모델 계산상한(기본 350 barg)을 넘으면 오류로 계산 중지합니다. 안전밸브 방출로 대체하지 않습니다.

`summary.json → stop_history`:
- 정지 요청/완료 시각
- 요청/완료 당시 Bank 압력
- 차단 요청 이후 추가 유입량

이 순서는 **오프라인 등가 시험용**입니다. 실제 압축기 패키지의 정지·Unload·밸브 C&E를 재현한 것이 아닙니다. 배관 잔류재고와 압력파는 제외됩니다.

## 9. 결과 저장과 재현

`결과 CSV`에서 폴더를 선택합니다. 같은 폴더의 같은 이름은 덮어씁니다.

- `trend.csv`: 처음부터 전체 기록. Bank별 P/m/SP/HH/최대압력, 밸브 명령/실개도/소유자, 유량, 참조전력량, 규칙 상태.
- `events.csv`: SP 변경, 규칙 발동/복귀, 차단 요청/완료, 거부된 명령.
- `initial_config.json`: 해당 실험 시작 시 입력.
- `config.json`: 현재 입력(운전 중 변경을 반영).
- `summary.json`: 최종 상태 및 종료별 잔류 유입량.

`config.json`은 **현재 재고에서 재개하는 Snapshot이 아니라 초기상태를 정의하는 입력파일**입니다. 실험 재현은 initial_config와 events의 변경시점을 함께 사용합니다. 실시간 SP 변경은 로그로 남으며 자동 재생 스크립트는 이번 범위 밖입니다.

화면 추세는 첫 8개 Bank까지 표시하고, 전체 1~32개 Bank는 상태표와 CSV로 확인합니다. HMI는 Bank 수에 따라 세로 스크롤됩니다.
